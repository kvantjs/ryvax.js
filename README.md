Ryvax.js is Kvant's full-stack React and TypeScript framework for building modern web applications with a coherent foundation across the frontend, backend, and operations. Just as Vercel presents Next.js as its framework for React, Kvant creates, maintains, and develops Ryvax.js for teams building complete products with React and TypeScript.

The framework brings together file-based routing, React server-side rendering (SSR), static site generation (SSG), hydration, streaming, typed API contracts, authentication, caching, jobs, health checks, observability, and portable Node.js deployment.

> Ryvax.js is developed by Kvant with a focus on architectural clarity, explicit contracts, and infrastructure freedom. Applications do not depend on a proprietary hosting platform.

## Why Ryvax.js?

Modern full-stack applications often need more than a UI renderer. They need predictable route discovery, server rendering, API behavior, request cancellation, bounded input, background work, cache semantics, deployment artifacts, and operational diagnostics.

Ryvax provides these contracts in one TypeScript-oriented framework while keeping external providers replaceable. Database, cache, queue, storage, metrics, identity, AI, and deployment integrations are modeled through explicit interfaces instead of being mandatory runtime dependencies.

## Features

### Application and routing

- File-based routing through `pages/` with support for dynamic segments and catch-all routes.
- App Router conventions through `app/`, including `page.tsx`, `route.ts`, `layout.tsx`, loading states, error boundaries, and route groups.
- Deterministic route manifests generated by the compiler.
- Typed request context with parameters, query strings, headers, body, abort signals, environment values, and runtime information.

### Rendering and frontend

- React 19 rendering with SSR, SSG, hydration, and HTML streaming.
- Static export for CDN-oriented sites.
- Client navigation primitives through `@kvantjs/ryvax.js/client`.
- Server actions with stable build-time identifiers and bounded, origin-checked transport.
- Experimental React Server Components track with an explicit compatibility boundary.

### APIs and HTTP

- TypeScript API handlers with named HTTP method exports.
- JSON, body, redirect, stream, `OPTIONS`, and safe `HEAD` response behavior.
- Request deadlines, abort propagation, bounded request bodies, and stable malformed-JSON errors.
- Middleware composition and validation contracts.

### Platform contracts

- Authentication, signed sessions, CSRF validation, authorization, and rate limiting primitives.
- Process-local response cache with TTL, stale-while-revalidate, tags, invalidation, and miss deduplication.
- Provider-neutral data cache, database, storage, metrics, and job queue interfaces.
- Health and readiness checks with structured reports and HTTP `503` behavior for unhealthy results.
- Structured logs, request IDs, metrics hooks, audit events, resilience utilities, and request tracing.

### Developer experience

- `defineConfig()` for typed framework configuration.
- `ryvax generate` for deterministic route and configuration declarations.
- Optional TypeScript Server Plugin for route-aware diagnostics and completion.
- `ryvax doctor`, `ryvax routes`, `ryvax inspect`, `ryvax analyze`, and `ryvax benchmark` for project diagnostics and build inspection.
- Scaffolding through `create-ryvax-app` and ready-to-run React, SaaS, documentation, and API documentation templates.

### Deployment

- Portable Node.js deployment output.
- Vercel Build Output API adapter.
- Netlify Node Function adapter.
- Docker deployment output.
- Edge adapter primitives with explicit runtime boundaries.
- No claim of persistent filesystem, WebSocket durability, or universal serverless behavior: those properties depend on the deployment platform and application architecture.
